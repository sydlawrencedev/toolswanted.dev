## Design review, then design re-review

Wrote `reviews/design-review.md` — 16 findings on the live product, 7 public pages,
both themes, 320/390/768/1280px, 100/150/200% zoom. Then re-reviewed the fixes on
`feature/marketing-design-review` (commit `cdc89cd`) and wrote
`reviews/design-re-review.md`.

### Verdict: DOES NOT SHIP

10 fixed, 2 partially fixed, 4 not fixed, 0 regressed, 3 new findings introduced by
the fixes.

### The fixes that landed well

- **C1.** One `boardIsEmpty` flag drives the hero and the card area. The two halves
  cannot disagree now, because they read the same boolean.
- **C2.** The install snippet is 242 characters, down from 653. `word-break:break-all`
  is gone. Measured: 10 lines at 320px, **0 mid-word breaks**, URL intact on one line.
- **C3.** The tally is demoted below 560px — no slab, no inversion, same size and
  colour as the title. Ink ratio **2.20x -> 0.303x at 320px**, 3.50x -> 0.303x at 390px.
  The fix went further than I asked for and it is right.
- **H1, M1, M2, M4, L1, L4** fixed and tested. Six new test files, 28 assertions, and
  the good ones check the two-sided case — empty *and* populated — so a fix cannot
  become a deletion.
- **The publish gate is closed.** `getClusterBySlug` filters on `status = 'published'`,
  a differently-named `getClusterBySlugAnyStatus` serves the moderation surfaces, and
  the poster route refuses to serve a share card for an entry a reader cannot open.

### What did not get fixed

M3 (`/agents` tools table still hides its only meaningful column off-screen), L2 (OG
header still says "WANTED" twice), L3 (favicon still a red Helvetica W), L5
(`/privacy` still lights no nav item).

### What the fixes broke

**NEW-1, High.** The theme button's label reads `data-theme === 'dark'`, and
`data-theme` is only ever set by the script — `prefers-color-scheme` sets CSS custom
properties, not the attribute. So on a dark-mode reader who has never touched the
toggle, the button says **"Dark mode"** on a page that is already dark. Confirmed in
`board-390-dark.png` and `about-390-dark.png`. The fix for H3 was right; this is the
price of it and it is on every page.

**NEW-2, Medium.** The registry-check form's placeholder is 45 characters and the
field's inner width is 220px at 320px, so it clips mid-word: "Convert a PDF invoice
into stru". At 200% zoom on a 320px phone, seven characters. The *layout* was written
for the zoom case; the placeholder was missed.

**NEW-3, Low.** The weekly ticker says "Live, updated as wishes come in", eight
paragraphs below a paragraph that already says "This page updates as wishes come in".

### H4 went the wrong way

The caveat is now a separate labelled span and the restatement is gone, so it is
structurally better. But the stats line is 51 characters and the seednote is 111, so
the caveat's **share went from 55.8% to 68.1%**. The absolute length fell; the
proportion rose. The fix asked for "the count and the label". It should read "60 are
ours, marked seeded" — the full explanation is already on `/about` and it is good
there.

### The lesson worth keeping

**A fix that makes the thing right can make the ratio wrong.** H4 shortened the
caveat and shortened the sentence it qualified, and the caveat ended up owning more
of the paragraph. When a review asks for "the count and the label", measure the
**share**, not the length. Length went down and the proportion went up, and only the
proportion is what a reader feels.

**A label has to describe the state the reader is in, not the state the code stores.**
NEW-1 is the same class of bug as C1: two sources of truth. The button asked
`data-theme`, the page renders `prefers-color-scheme`, and nothing reconciled them.
The fix is to read the *rendered* theme, not the attribute.

### Verification and its limits

This session had **no shell and no browser automation**, so I could not run
`scripts/audit-browser.mjs` or `scripts/check-pages.mjs` myself, and the prior
review's `.audit/_review-*.mjs` measurement scripts are no longer in the tree. What
I had: the audit's own committed output (`.audit/report.json` — 336 page loads, 0
findings, 0 console errors), the regenerated screenshots, the rendered HTML and CSS
fetched over HTTP, and measurement computed from that CSS.

The C3 ink ratio uses the **prior review's own model**, calibrated so the OLD 320px
case reproduces its measured 2.20x exactly (k = 0.3048), then applied unchanged to old
and new. The calibration check is printed in the report so it can be checked.

`GET /wish?need=...` and `POST /api/wish` return **500** on this dev server for any
need long enough to validate. **Not a defect in the branch**: every route that calls
Workers AI fails the same way (`/api/search?q=pdf` is 500 too), because
`npm run dev:local` is `wrangler dev --local` and the local AI binding has no
credentials here. Production binds AI. I would have filed it as Critical if it were
real — the new hero form posts to exactly that route.

### The audit still cannot see

It passed every one of the sixteen findings and all three new ones. Six new test
files are all unit tests over rendered HTML, so none of them can see a clipped
placeholder — that is a layout fact. Three assertions it still cannot make, and this
branch is the right place to add them:

1. **No element's label may describe a state the element is not in.** Compare the
   button's `textContent` to the computed background. Would have caught NEW-1.
2. **No placeholder may be clipped by its own field.** Would have caught NEW-2.
3. **The visible content of a table must not require a horizontal scroll to be
   understood.** The audit checks that the *document* does not overflow; it does not
   check that the first column carries the meaning. Would have caught M3, three
   reviews running.
