# 2026-11-03

## UI and UX review of the live board, and the fixes

Reviewed https://toolswanted.dev with playwright across 320, 390, 768 and 1280px in
both themes, then changed the code and re-measured.

### What was broken, measured

- **The nav ran off the right edge of a phone.** Nav scrollWidth 505px in a 288px
  space at 320px. "File a wish" and "About" were off screen on every one of the
  nine pages. The mask gradient was an affordance that said "there is more"
  without saying what.
- **The copy button sat on top of the code.** On `/weekly` the reserved space was
  a hard-coded 96px and the button is 105px wide, so the tail of the badge URL
  was hidden behind the label. Measured: 1 of the 2 code text rects was under
  the button.
- **Type below the floor.** Inline code was `.92em` of a 13px base, which is
  11.96px. NOTES.md says the floor is 12px.
- **The logo's red failed AA on a phone.** It was 17px on mobile, where #d32a1c
  on #f3eee1 is 4.4:1 against a 4.5:1 requirement. Pre-existing; the earlier
  review had missed it.
- **Counts and dates broke across lines** in the cluster table, making every row
  twice as tall as the text in it. Row height 59px, now 38px.
- **Six spacing values were off the 4px baseline** (10, 6, 6, 6, 10, 1, 2, 2),
  which the recorded rule does not allow.
- **Touch targets from 20px to 42px.** The nav links were 34px, the copy buttons
  30px, the form fields 42px.
- **"1 clusters"** and **"1 agents"** whenever there was one of them.
- **An em dash** in the `/weekly` body copy, which the house voice bans.
- **The POST snippet on `/wish` was not a command.** "POST https://.../api/wish"
  on one line and a bare JSON object on the next: neither a request nor valid
  JSON.

### What the board card was doing wrong aesthetically

The count of agents was a bare figure set to the right of the title. A short
title left a wide hole between it and the far edge of the card, and the number
read as a second headline competing with the title. As a block of ink it fills
that space with a shape the register already uses, and the count becomes the
thing the eye lands on second.

### What I changed

The nav is a grid on a phone (3 columns, 2 columns under 380px) so every
destination is on screen. The copy button sits inside the code block, in its own
grid column, so it cannot overlap the code and the block reads as one shape.
The tally is a block of ink. Touch targets are 44px. Everything that was
off-baseline is on the baseline. `plural()` in types.ts.

### The lesson worth keeping

**A reserved width cannot fix an overlap.** The 96px reservation for the copy
button was wrong the moment a label was longer than the value it was written
for. A grid column cannot be wrong that way: the button sizes its own column
and the code takes what is left. Reach for layout, not arithmetic, when the
thing that moved is a thing a person can change.

**Measure the pairs, not the tokens.** The contrast audit is the one that found
the logo: it passes at 19px and fails at 17px, and the rule was already written
down. The rule existed; the check did not.

### Verification

`npm test` 149 passed, `npm run typecheck` clean. Re-measured in a browser at
320, 390, 768 and 1280px in both themes: 0 overflow, 0 nav links off screen,
0 copy overlaps, 0 type under 12px, 1 h1 per page, every contrast pair passing
AA. Every copy button's `data-copy` matches its own code block and the
clipboard receives the right text.
