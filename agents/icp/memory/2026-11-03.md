# 3 November 2026

## The audience review of Tools Wanted

Asked to review the audience definition and judge whether the product knows who
it is for. Another agent was working in the same tree at the same time (it
was doing the snippet-header fix and the poster-staleness work), so I kept my
changes to the definition, the copy and the count bug, and left its files
alone.

### The audience, canonically

Two audiences, and they are not the same size.

- **The agent, at the moment it is blocked.** Mid-task, not browsing. Wants to
  say what is missing in one plain sentence and get on with the work. No
  account, no API key, one call.
- **The builder, at the moment they are choosing what to build next.** Someone
  who builds MCP servers, agent tools or agent infrastructure, and who would
  rather read what agents got stuck on than guess.

**The builder is primary.** The agent is the data source; the builder is the
reader the ranking exists for. A board of agent wishes only earns its keep
when it changes what somebody builds.

**The operator is not an audience.** It may be named on the About page, and it
is, because that is disclosure, not an audience. Its needs are a subset of the
builder's.

### What is observed, and what is not

There is no user research in this repo. No interviews, no surveys, no
analytics. Everything about what agents or builders want is `[hypothesis]`.

The one `[observed]` thing, and it is narrow: 10 independent agents filed
unseeded wishes against the published cluster, and the board counted them as
independent agents. That shows the filing path works. It does not show that
the wish text represents what agents generally want, that agents want the
board, that builders read the board, or that any of it converts into a
shipped tool.

The whole board's 18 agents sit behind 4 distinct IP addresses, so most of
that number is the operator's own machines counted more than once. That is a
measurement, not a caveat.

### The contradictions I found, and fixed

1. **`/about` said "Every wish on this board was filed by an agent that was
   blocked."** False. 60 of 108 wishes were filed by the operator's own agents
   to seed the board. Those agents were not blocked on anything.
2. **The tagline said "filed by the agents themselves."** It was in the
   footer on every page, the MCP instructions an agent reads, the README, the
   registry listing, and the About page. Changed to "ranked by how many
   independent agents asked for the same thing".
3. **The board hero said "capabilities agents have actually got stuck on".**
   Removed "actually", and added what the ranking actually rests on: the
   agent count, not the wish count.
4. **`/build` collected a repository URL and then dead-ended at a 503.** Now
   renders from the deployment's own configuration: the notice is at the top,
   the form is gone, and the reader is given what does work.
5. **The entry page made the same claim promise.** Now says claiming is not
   switched on.
6. **`/weekly` promised a claim path that dead-ended.** Same fix.
7. **`week_count` said 26 this week against 25 wishes in total.** A running
   counter that was never reset at the week boundary, and the merge
   recomputed `count` from the wishes while leaving `week_count` alone. Now
   counted from the wishes in both the recording path and the merge, with
   `migrations/0008_week_count.sql` to fix the rows already stored.

### What I could not do

`npm run og:sync` needs the production `ADMIN_TOKEN`, which is not in the
repo. The poster for the published entry still says 4 agents where the board
says 10. The other agent added a fallback: a stale poster is not advertised
as the og:image, so the default card is used instead. That is a workaround,
not a fix. Someone with the token has to run the script.

### The smallest next thing to learn

Not more agents. One builder. A claim is the first evidence the board changes
what somebody builds, and it costs nothing but turning on GitHub sign in and
asking one person who builds MCP servers to look at the one entry. The
question is not "would you build this" but "did the board change your mind",
and the only way to know is to watch one builder arrive and one claim land.
