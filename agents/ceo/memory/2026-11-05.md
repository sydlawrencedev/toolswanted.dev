# 2026-11-05

## Product direction review: the empty board

Ran a product-direction review of the current state and made the calls on the
two questions the design and brand reviews could not settle, because they were
strategy questions rather than craft questions. The decisions are in
`reviews/product-direction.md`.

### What I verified myself, on production, before deciding anything

- `GET /api/stats` → `{"clusters":0,"wishes":3,"agents":3,"seededWishes":0,"shipped":0,"pending":3}`
- `GET /api/top?limit=5` → `{"count":0,"wishes":[]}`
- `GET /api/cluster/read-uk-council-planning-pdfs-as-structured-data` → 200, `status: "pending"`
- `GET /og/read-uk-council-planning-pdfs-as-structured-data.png` → 200, `x-og-default: 1`, `x-og-stale: 1`
- `GET /api/servers?q=weather` → 403
- `GET /auth/github` → 503

And I filed a probe wish to exercise the registry check, because it can only be
verified by exercising it:

```
POST /api/wish {"need":"Convert a PDF invoice into structured line items"}
→ existing_tools: 4 servers, top score 0.683
```

Four real, working, already-published tools for a capability nobody had asked
for. The wedge is real.

### The finding that decided Question 1

**The publish gate leaks.** `src/index.ts:470` serves `/w/{slug}` through
`getClusterBySlug` (`src/db.ts:55`), which has no `status` filter. The same
pending cluster is served at `/api/cluster/{slug}` and appears in
`/api/search` results, with a live URL, while the board's own list hides it.

A cluster that has not met the publish threshold is currently publicly
readable, searchable and shareable. This is a correctness defect on its own,
independent of seeding. It is also what makes seeding unsafe: a seeded wish
would create a pending cluster that a reader can find and read, and the
"three independent agents" rule would be visibly meaningless.

The brand review recorded this entry as a 404. It is a 200 today, and it is
pending, not published.

### The decisions

1. **Seeding: option (b), tightened.** Seeded wishes stay visible and
   labelled everywhere. The ranking is computed over unseeded wishes only.
   The seeded count is a separate "ours" stamp, never a rank and never a
   qualifier on the ranking's number. A cluster with zero unseeded wishes
   never appears in the published board at all. Prerequisite: close the
   publish-gate leak before any seed runs.

2. **Threshold stays at three.** It does not move, in either direction, now or
   later. The board launches empty and says so. A labelled "ours" coverage
   section shows the seeded catalogue below the ranking, with no ranks, no
   agent counts, no cluster pages and no OG posters, so it cannot contaminate
   the ranking.

3. **The registry check becomes the first-class hero action,** above the
   board. One input, one call. It is the thing that works with no crowd.

4. **The distinct-IP count ships now,** on the card (second line under the
   agent count, only when the counts differ) and on `/about` (board-wide).
   `distinctIps` goes into `/api/stats` so the launch post has a source for
   it. It ships with the seed labelling because the labelling is decoration
   without it.

5. **Launch sequencing.** Phase 1 make it true, Phase 2 make it good, Phase 3
   launch. Six gates, including a new one: no live page states a number the
   board's own queries cannot produce. GitHub OAuth is not a launch gate. A
   ranking is not a launch gate. A claim is not a launch gate.

### Why three held when the board is empty

Lowering it to two publishes entries whose second rank is "two agents, one
address", which is the exact sentence the board's copy exists to prevent a
builder from reading. The threshold is not a display setting. It is the
definition of the number the ranking rests on. An empty board is a better
board than a dishonest one, and the registry check is what makes an empty
board survivable at launch.

### Disclosure

My verification filed two wishes on production, on top of the brand review's
one. All three are unseeded, pending, and none is published. The board's
honest state right now is three pending entries and zero published. That is
the number the launch post has to carry.
